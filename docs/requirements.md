# 需求理解与功能拆分（requirements.md）

> 对应题目《Local AI Speech-to-Text Web Application》

---

## 1. 需求理解

### 1.1 一句话概括

在 **2 个自然日**内交付一个可在 **Windows 11 + 普通 CPU** 上运行的
**B/S 架构本地语音识别系统**：浏览器负责录音/上传与结果展示，后端使用
**本地开源 ASR 模型**把中文普通话或英语语音转成文字，全程不依赖云端识别服务，
并提供自动化测试、测试音频、运行文档与开发过程记录。

### 1.2 需求本质与关键约束

| 约束 | 我的理解 |
| --- | --- |
| "本地" | 识别推理必须发生在本机进程内；不得调用云端 ASR API；不得用浏览器 Web Speech API 替代（那是云端能力） |
| "可复现" | 评委在一台干净的 Windows 11 上，按 README 两条命令即可启动；不得要求 Docker、Node.js、数据库、编译原生依赖 |
| "CPU 必须支持" | 不能把 CUDA 当必要条件；模型必须能在普通 CPU 上以可接受的速度推理 |
| "断网可用" | 仅首次权重下载可联网；之后识别过程不得触网 |
| "必须用 OpenCode" | 主要开发工具为 OpenCode，且需提供三阶段过程证据 |
| "必须区分 Mock 与真实模型测试" | 常规测试全部 Mock 且不下模型；另需真实模型的中英文识别验证 |

### 1.3 关键假设（若假设不成立请指出）

1. **评委环境**：Windows 11 x64，Python 3.12 可用，Chrome/Edge 最新版，能访问
   `127.0.0.1:8000`。首次运行可联网下载模型权重。
2. **麦克风**：评委机器有可用麦克风；即使没有，上传识别路径也能独立验证全部
   必做功能（题目 §9.6 正有此意）。
3. **语言范围**：只要求中文普通话与英语，不含粤语、方言；不做语音翻译。
4. **并发规模**：单用户本机使用，无需多用户并发与鉴权（题目 §8 明确排除）。
5. **实时性**：题目明确"不要求原生流式、不设严格毫秒级延迟"，因此允许用
   "分片 + 累积重识别"近似实现。
6. **网络受限时**：项目已把国内源作为默认（pip 用清华镜像、模型默认从 ModelScope 下载、
   Hub 端点默认 `hf-mirror.com`）；仍无法访问时可通过 `HF_ENDPOINT` 指向其他镜像，
   或把权重目录 `models/` 直接拷贝到目标机器实现完全离线（见 README §3.4）。
   这不改变"本地推理"的性质。

## 2. 功能拆分（按必做 / 加分）

### 2.1 F1 浏览器麦克风录音（必做）

| 子需求 | 实现要点 | 状态 |
| --- | --- | --- |
| 请求麦克风权限 | `navigator.mediaDevices.getUserMedia` | 已实现 |
| 开始 / 停止录音 | `MediaRecorder` + 显式按钮状态机 | 已实现 |
| 状态与时长展示 | 状态灯（就绪/录音中/识别中/完成/失败）+ 计时器 + 进度条 | 已实现 |
| 停止后提交识别 | `stop` 事件回调中组装 Blob 并 POST | 已实现 |
| 单次最长 60 秒 | 计时器到 60 s 调用停止逻辑；进度条同步 | 已实现 |
| 录音中明确提示 | 状态随阶段变化；按钮禁用态互斥 | 已实现 |
| 失败/权限被拒提示 | `NotAllowedError`/`NotFoundError` 等映射为具体中文提示 | 已实现 |
| 可再次录音 | 识别完成后恢复按钮与计时器 | 已实现 |

### 2.2 F2 音频文件上传（必做）

| 子需求 | 实现要点 |
| --- | --- |
| 至少支持 WAV | 标准库 `wave` 快路径 + PyAV 主路径 |
| 支持浏览器录音格式 | PyAV 解码 `audio/webm;codecs=opus`（Chrome/Edge 默认） |
| 与录音共用后端逻辑 | 两者最终都走 `services/transcribe.py::transcribe_bytes` |
| 不支持格式/无法解码有提示 | 415 `UNSUPPORTED_FORMAT` / 400 `DECODE_FAILED`，前端展示同一错误结构 |
| 大小限制 | 后端 10 MB（`MAX_UPLOAD_MB` 可调），前端预校验并给提示 |

### 2.3 F3 本地中英文语音识别（必做）

| 子需求 | 实现要点 |
| --- | --- |
| 中文普通话识别 | faster-whisper，`language="zh"` |
| 英语识别 | `language="en"` |
| 页面可选语言 | `<select>` 提供 zh / en；别名（zh-CN、English 等）在服务端容错归一化 |
| 返回文字给页面 | `POST /api/transcribe` → `text` 字段 |
| 可连续识别 | 无状态接口，模型单例复用 |
| 不做翻译 | 仅转写，不调用任何翻译逻辑 |
| 中英混合自动检测（加分） | 引擎支持 `language=None` 自动检测（`ASR_AUTO_DETECT_LANGUAGE` 开关） |

### 2.4 F4 识别结果展示（必做）

| 展示项 | 实现 |
| --- | --- |
| 当前识别语言 | 「识别语言」卡片 |
| 录音/识别中/完成状态 | 状态灯 + 文案 + 结果区「状态」字段 |
| 识别文本 | 结果区 `<pre>`，可选中 |
| 音频时长 | `duration_seconds` |
| 处理耗时 | `processing_seconds` |
| 过程有反馈 | 状态实时更新；后端同步推理（短音频秒级返回） |
| 可复制 | 「复制」按钮（`navigator.clipboard` + `execCommand` 降级） |

### 2.5 F5 异常处理（必做）

| 场景 | 预期 | 实现 |
| --- | --- | --- |
| 拒绝麦克风权限 | 提示原因，页面不崩 | `NotAllowedError` → 明确中文提示 + 重试指引 |
| 未检测到麦克风 | 明确错误 | `NotFoundError` → "未检测到可用的麦克风设备" |
| 空文件 / 损坏音频 | 拒绝并返回错误 | 400 `EMPTY_FILE` / 400 `DECODE_FAILED` |
| 格式不支持 | 明确提示 | 415 `UNSUPPORTED_FORMAT` |
| 录音超 60 秒 | 自动结束 | 计时器触发停止并提示"已达上限" |
| 模型加载失败 | 可理解的失败信息 | 启动预热失败不阻断服务；请求返回 503 `MODEL_UNAVAILABLE` 并给出初始化指引 |
| 识别中后端出错 | 页面提示失败、可重试 | 500 `INFERENCE_FAILED`；前端恢复按钮 |
| 音频无可识别语音 | 不崩溃，空结果 | 200 + `text: ""`，页面提示"未检测到有效语音" |
| 上传文件过大 | 拒绝 | 413 `FILE_TOO_LARGE`，上限 10 MB |

### 2.6 F6 实时识别（加分项）

| 子需求 | 实现 |
| --- | --- |
| 持续采集麦克风 | `AudioWorklet`（不可用时降级 `ScriptProcessorNode`） |
| 分片发送后端 | 降采样到 16 kHz、int16 PCM，每约 0.5 s 一片经 WebSocket 发送 |
| 后端本地模型处理 | 累积缓冲 + 滑动窗口重识别 |
| 页面持续更新 | `partial` 消息实时渲染到「实时识别中」卡片 |
| 停止输出最终文本 | `stop` → `final` 消息，写入结果区并展示时长/耗时 |
| 失败可降级 | WebSocket 建立失败时自动回退到 F1 整段模式，必做功能不受影响 |

## 3. 边界条件与默认取值

| 项 | 取值 | 依据 |
| --- | --- | --- |
| 单次录音上限 | 60 s | 题目 F1 |
| 上传大小上限 | 10 MB | 题目 F5 建议值 |
| 目标采样率 | 16 kHz 单声道 float32 | Whisper 输入要求 |
| 支持语言 | zh / en | 题目 F3 |
| 处理耗时统计范围 | 解码 + 推理（不含首次权重下载） | 题目 §4.2 |
| 无有效语音 | 200 + 空文本 | 题目 F5 |
| 单进程串行推理 | 是 | 题目 §8 不要求并发 |

---

## 4. 明确不做（题目 §8）

用户登录与权限、数据库存储、识别历史管理、说话人识别、降噪算法、语音翻译、
TTS、模型训练/微调、分布式与多用户并发、手机端适配、商业级实时字幕性能。
